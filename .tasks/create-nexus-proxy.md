# Настройка Nexus как кеширующего npm-прокси и проверка офлайн-работы

**Цель**: в уже запущенном Docker-контейнере Nexus (имя образа `my-private-nexus`, порт 8081) автоматически создать npm-прокси-репозиторий и проверить его работу. В итоге в проекте должен появиться `.npmrc`, указывающий на этот Nexus, а любой скачиваемый npm-пакет должен попадать в кеш Nexus. После этого проект должен устанавливаться без интернета — все нужные пакеты берутся из кеша.

**Исходные условия**: контейнер Nexus запущен; известны логин и пароль администратора (или они лежат в `.env` как `ADMIN_USER` / `ADMIN_PASS`); в `nexus.properties` включено создание Groovy-скриптов (`nexus.scripts.allowCreation=true`).

**Что должен сделать агент**:

1. **Создать npm proxy-репозиторий**
   Через REST API или Groovy-скрипт создать npm proxy-репозиторий с именем `npm-proxy` и remote URL `https://registry.npmjs.org/`. Именно сюда будут складываться скачанные пакеты.

2. **Создать npm group-репозиторий (рекомендуется)**
   Создать npm group-репозиторий с именем `npm-group`, добавив в его состав `npm-proxy`. Group удобен тем, что при добавлении внутренних приватных hosted-репозиториев URL для клиента менять не придётся. Клиент будет обращаться к `http://localhost:8081/repository/npm-group/`.

3. **Создать `.npmrc` в проекте**
   В корне тестового проекта записать:
   ```
   registry=http://localhost:8081/repository/npm-group/
   ```
   Если Nexus не разрешает анонимное чтение, добавить строку авторизации (`_auth` с base64 от `username:password`). Для локальной разработки лучше сначала разрешить анонимное чтение, чтобы не хранить пароль в файле проекта.

4. **Проверить, что кеш работает**
   Выполнить в проекте чистую установку (например, `npm install lodash`). Затем через API или веб-интерфейс Nexus убедиться, что пакет `lodash` появился в Browse репозитория `npm-proxy`. Это докажет, что пакет прошёл через Nexus, а не был скачан напрямую из интернета.

5. **Проверить работу офлайн**
   Временно отключить сеть (или выключить Wi-Fi), удалить `node_modules` в проекте и снова выполнить `npm install`. Если установка прошла успешно — кеш Nexus работает, задача выполнена.

**Критерии приёмки**:
- В Nexus существует репозиторий `npm-proxy` (или `npm-group`);
- В корне проекта есть `.npmrc` с registry, указывающим на Nexus;
- Как минимум один npm-пакет устанавливается из кеша после отключения интернета.

**Примечание**: Groovy-скрипты в Nexus 3.77.2 ещё работают, но Sonatype объявила об их будущем удалении. Если агент столкнётся с отказом при создании скрипта (403), сначала проверить `nexus.scripts.allowCreation`; если проблема останется — перейти на чистый REST API (`POST /service/rest/v1/repositories/npm/proxy`).
