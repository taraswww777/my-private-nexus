# my-private-nexus

Репозиторий артефактов на базе **Sonatype Nexus Repository OSS**, упакованный в Docker Compose с автоматической инициализацией и готовой конфигурацией для npm.

## 🚀 Быстрый старт

Самый важный раздел. Сервис поднимается одной командой.

### 1. Подготовка окружения

Скопируйте пример переменных окружения и при необходимости отредактируйте:

```bash
cp .env.example .env
```

### 2. Запуск сервиса

```bash
docker compose up -d
```

При первом запуске скрипт `init-nexus.sh` автоматически выполнит первичную настройку (создание репозиториев, применение паролей и т.д.).

### 3. Получение пароля администратора

Если пароль не был задан в `.env`, его можно получить из контейнера:

```bash
docker exec -it nexus cat /nexus-data/admin.password
```

Логин по умолчанию: `admin`.

### 4. Доступ к веб-интерфейсу

Откройте в браузере: `http://localhost:8081`

### 5. Подключение npm

В репозитории уже есть файл `.npmrc`, который указывает npm на локальный group-реестр Nexus. Если вы используете его в проекте, просто скопируйте `.npmrc` в корень вашего проекта или выполните:

```bash
npm config set registry http://localhost:8081/repository/npm-group/
```

## 📦 Кейсы использования

### Приватный npm-реестр

После запуска Nexus в нём создаётся группа `npm-group`, которая объединяет локальный hosted-репозиторий и прокси на публичный npm. Это позволяет:

- Публиковать внутренние пакеты (`npm publish --registry http://localhost:8081/repository/npm-hosted/`)
- Кешировать публичные пакеты и ускорять сборки
- Не зависеть от доступности registry.npmjs.org

### Прокси для Docker-образов

Nexus может выступать как pull-through cache для Docker Hub. После создания docker-репозитория в веб-интерфейсе укажите его как mirror в конфигурации Docker daemon.

### Хранение Maven-артефактов

Стандартный сценарий для Java-проектов: настройте `distributionManagement` в `pom.xml` на URL hosted-репозитория Nexus (например, `http://localhost:8081/repository/maven-releases/`).

## 🗂 Структура проекта

| Файл | Назначение |
|------|------------|
| `docker-compose.yml` | Описание сервиса Nexus и томов данных |
| `init-nexus.sh` | Скрипт автоматической инициализации репозиториев |
| `.env.example` | Пример переменных окружения (пароли, порты) |
| `.npmrc` | Конфигурация npm для работы с локальным реестром |
| `.dockerignore` | Исключения для сборки Docker-образа |
| `package.json` | Зависимости и скрипты (если используются) |

## ⚙️ Конфигурация

Основные параметры задаются через `.env`:

```env
NEXUS_PORT=8081
NEXUS_ADMIN_PASSWORD=your_secure_password
```

После изменения `.env` перезапустите сервис:

```bash
docker compose down && docker compose up -d
```

---

## 🛑 Остановка и очистка

```bash
# Остановить без удаления данных
docker compose down

# Остановить и удалить volume с данными (все артефакты будут потеряны)
docker compose down -v
```

---

## 📝 Примечания

- Данные Nexus хранятся в Docker volume, поэтому перезапуск контейнера не приводит к потере артефактов.
- Скрипт `init-nexus.sh` идемпотентен: повторный запуск не ломает уже созданную конфигурацию.
- Для production-использования рекомендуется настроить reverse proxy (Nginx/Traefik) с TLS и вынести `NEXUS_ADMIN_PASSWORD` в секреты.
